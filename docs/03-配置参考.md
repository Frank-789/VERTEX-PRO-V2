# 配置参考

> 配置即数据 —— 改行为改 JSON，不改代码。
> 所有配置文件缺失或校验失败时都会**回退到内置默认值并打日志**，不会让服务起不来。

---

## 一、配置来源一览

| 配置 | 位置 | 进 git？ | 缺失时 |
|---|---|---|---|
| AI 供应商路由 | `config/providers.json` | ✅ | 回退内置默认（只有 DeepSeek 一条链） |
| 提示词 | `prompts/default/*.md` | ✅ | 回退代码里的兜底人设 |
| 提示词覆盖 | `prompts/user/*.md` | ❌ gitignore | 无覆盖，用 default |
| 密钥与凭证 | `.env` | ❌ gitignore | 对应工具显示「未配置」 |
| 可写状态 | `data/`（或 `$DATA_HOME`） | ❌ gitignore | 自动创建 |

## 二、`config/providers.json`

供应商按**能力**分组，每组是一个**有序降级链**：前一个失败自动试下一个。

```json
{
  "chat":     [ { "id": "deepseek", ... }, { "id": "kimi", ... }, { "id": "mock", ... } ],
  "planning": [ ... ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 供应商标识。出现在 `/health` 与日志里 |
| `provider` | 适配器类型。目前只有 `openai-compat`（OpenAI 兼容的 `/v1/chat/completions`） |
| `base_url` | 接口根地址 |
| `model` | 模型名 |
| `api_key_env` | **密钥从这个环境变量名读** —— 密钥本身永远不写进 JSON |
| `timeout` | 单次请求超时（秒） |

**以 `$` 开头的键会被忽略**，用来写注释（JSON 没有注释语法）：

```json
{ "$comment": "这行会被跳过" }
```

### 两条链的区别

| 链 | 用途 | 默认超时 |
|---|---|---|
| `chat` | 对话作答 | 60s |
| `planning` | 需要更多思考的规划任务 | 90s |

`planning` 留空时会**自动复用 `chat`**，所以只配一条链也能跑。

### 降级是怎么发生的

`core/provider_router.py` 先用 `os.getenv(api_key_env)` **过滤掉没配密钥的供应商**，
所以「配了 mock 但没配 key」不会让 mock 被误用 —— 有真 key 时真 key 优先。

没有 **任何** 供应商可用时，服务能起来，但对话会明确报错，不会静默返回空答案。

## 三、环境变量

### 路径覆盖（通常不用改）

| 变量 | 默认 | 说明 |
|---|---|---|
| `DATA_HOME` | `<仓库根>/data` | 可写状态根。**容器里设成 `/data` 并挂卷** |
| `CONFIG_HOME` | `<仓库根>/config` | 配置目录（只读） |
| `PROMPTS_HOME` | `<仓库根>/prompts` | 提示词目录 |
| `LOG_LEVEL` | `INFO` | 日志级别 |
| `EVENT_LOG` | `1`（开） | 设成 `0` / `false` / `off` 就**完全不写事件日志**。在意用户内容落盘的部署用得上 |

> 第一代把知识库路径硬编码成 `~/Desktop/Vertex/知识库`，在容器里必然失效且**静默降级**。
> V2 里不存在任何硬编码绝对路径。

### AI 供应商

变量名必须与 `providers.json` 里的 `api_key_env` **对得上**，否则路由找不到密钥。

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | 主供应商 |
| `KIMI_API_KEY` | 降级供应商 |
| `MOCK_API_KEY` | 开发用假供应商，**填 `dev` 即可**，不花钱 |

### 数据采集

**不配也不影响启动** —— 对应工具在 `/health` 里显示为 `pending`，调用时明确报错。

| 变量 | 说明 |
|---|---|
| `APIFY_TOKEN` | Apify 凭证 |
| `APIFY_DEFAULT_ACTOR` | 默认 Actor |
| `APIFY_ACTOR_<平台>` | 按平台单独指定，如 `APIFY_ACTOR_AMAZON` |
| `EBAY_API_KEY` | eBay Browse API |
| `EBAY_MARKETPLACE` | 默认 `EBAY_US` |

### 定时任务

不配就能用。任务格式和调度语义见 **[04-定时任务.md](04-定时任务.md)**。

| 变量 | 默认 | 说明 |
|---|---|---|
| `ISSUE_SCHEDULER` | `1`（开） | 设成 `0` / `false` / `no` / `off` 就**不跑后台循环**，只保留手动触发。**测试环境必须设 0** |
| `ISSUE_TICK_SECONDS` | `30` | 扫描间隔（秒）。任务最多晚这么久被发现 —— 代价仅此而已，因为判据是「上次跑之后有没有命中过」而不是「此刻是否命中」，所以调大没有副作用 |
| `ISSUE_MAX_PER_TICK` | `5` | 单轮最多执行几个任务。防止机器睡一夜醒来，二十个任务同时开跑把供应商并发配额一次打满。没轮到的下一轮继续，**任务欠着不会丢** |
| `ISSUE_DEFAULT_TZ` | `Asia/Shanghai` | `when:` 里没写 `timezone` 时用哪个。默认东八区 —— 默认 UTC 会把「早上九点」变成下午五点 |

## 四、提示词双层覆盖

```
prompts/
  default/persona.md    ← 进 git，随仓库分发
  user/persona.md       ← gitignore，本地覆盖
```

加载顺序：**先找 `user/`，再找 `default/`**，取第一个非空文件。

改语气、改报告格式、加禁用词，都**不需要动代码**，也不需要污染版本库。
第一代把提示词硬编码在 4 个文件、前后端各一份 —— 改一处必忘另一处。

### 人格提示词里已经写死的规则

- 先给结论，再说依据
- 数字要具体，不确定就说不确定
- **一条回复最多 1 个表情**
- **用户说亏钱了、遇到纠纷了 —— 禁用表情**

表情包语法是 `[[sticker/<name>.svg]]`，可用名称见
`apps/web/public/stickers/vertex-default/pack.json`。

## 五、工具的健康状态

`GET /health` 会区分三态，排障不用猜：

```json
{
  "ok": true,
  "providers": ["mock"],
  "tools": {
    "ready":   ["apify.scrape", "profit.calc"],
    "pending": ["ebay.search"]
  }
}
```

| 状态 | 含义 |
|---|---|
| `ready` | 依赖齐备，可直接调用 |
| `pending` | **缺凭证**，调用会明确报错（绝不返回编造的数据） |

纯计算类工具（`profit.calc`）不需要任何凭证，因此永远 `ready`。

## 六、开发期热重载

改了 `providers.json` 或提示词但不想重启：

```python
from src.core.config import reload_config
from src.core.prompts import reload_prompts

reload_config()    # 清 providers 缓存
reload_prompts()   # 清提示词缓存
```

两者都用了 `lru_cache`，因此生产环境下读取是零成本的。

## 七、`data/` 目录里有什么

全部可写状态都在这里（或 `$DATA_HOME`）。容器里挂一个卷就全带走了。

| 子目录 | 内容 | 格式 |
|---|---|---|
| `sessions/` | **对话**：谁说了什么 | 一会话一文件，JSONL |
| `event-log/` | **运行过程**：每一步干了什么、多久、拿到什么 | 一天一文件，JSONL |
| `issues/` | **任务定义**（归你所有，手写手改） | 一任务一 `.md`，frontmatter 声明排期 |
| `issues/.state.json` | **任务状态**（`lastRun` / 累计次数 / 上次结果） | 单文件 JSON，原子替换 |
| `inbox/` | **任务产出的报告** | 一次运行一 `.md`，文件名即索引 |
| `workspaces/` `cache/` | 预留给后续阶段 | — |

> **任务定义和任务状态为什么分开放？** 见 [04-定时任务.md](04-定时任务.md) 第三节。
> 一句话：状态写回 `.md` 会和你的编辑器打架，而且写到一半崩溃就把任务定义弄坏了。

### 为什么对话和运行过程要分开

因为**用途不同，可见性也不同**：

- `sessions/` 会被回灌给模型当历史。里面**只有自然语言** ——
  工具返回的原始 JSON 如果塞进去，既白烧上下文，又会污染下一轮对话。
- `event-log/` 是给**人**看的，模型永远读不到。工具的**完整输出**只在这里。

两条链路的日志都验过：跑完一轮对话，`sessions/` 里是干净的问答，
`event-log/` 里是完整的工具原始返回。

### 事件日志记什么

一轮对话留下三笔，用同一个 `turn` id 串起来：

```jsonc
{"type":"turn.start","turn":"d7ada2a0ecc4","session":"e2e-eventlog-1",
 "preview":"成本45卖129，拼多多，算一下","chars":16}

{"type":"tool.call","turn":"d7ada2a0ecc4","session":"e2e-eventlog-1",
 "name":"profit.calc","status":"ok","ms":0,
 "args":{"cost":78,"price":199,"platform":"淘宝"},
 "result":"{...完整 JSON...}","resultChars":192,"truncated":false}

{"type":"turn.end","turn":"d7ada2a0ecc4","session":"e2e-eventlog-1",
 "ms":1892,"steps":1,"tools":1,"chars":372,"ok":true}
```

几点设计取舍：

- **每条都带 `session`**，虽然靠 `turn` 也能追回去 ——
  排查时最常干的事是 `grep <会话id>`，多一个字段省一步。
- **`preview` 只存前 500 字**。全文在 `sessions/` 里已经有了，
  这里再存一份纯属重复；留个开头是为了让日志自解释。
- **`result` 上限 64KB**，超出截断并把 `truncated` 置 `true`。
  「完整输出」正是这个日志存在的理由，但不能无界 ——
  一个返回 50MB 的工具能把磁盘写满。
- **按天分文件**，不是按会话。一次排障往往横跨几个会话；
  按天分可以直接 grep 一天的量。
- **写失败绝不抛异常**。日志是旁路，不能因为它挂掉整轮对话 ——
  但会打 `warning`，免得静默丢数据没人发现。

### 查日志

```bash
# 这一轮到底调了什么工具
grep e2e-eventlog-1 data/event-log/*.jsonl | python3 -m json.tool --json-lines

# 哪个工具最慢
jq -r 'select(.type=="tool.call") | "\(.name)\t\(.ms)ms"' data/event-log/*.jsonl | sort -k2 -rn | head

# 失败率
jq -r 'select(.type=="tool.call") | .status' data/event-log/*.jsonl | sort | uniq -c
```

保留 **30 天**，启动时自动清理过期文件（`event_log.prune()`）。
想改天数就调这个函数，或者干脆定期把 `event-log/` 归档走。
