# 部署指南

> **一句话原则**：Vercel 只承载 UI，智能体运行时永远跑在常驻进程里。
> 这不是偏好，是物理限制 —— 见下文第四节。

---

## 一、本地开发（已验证可用）

```bash
git clone https://github.com/Frank-789/VERTEX-PRO-V2.git
cd VERTEX-PRO-V2

# 后端依赖
cd apps/api && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && cd ../..

# 前端依赖
cd apps/web && npm install && cd ../..

# 配置
cp .env.example .env
```

### 没有 API key 也能跑通全链路

仓库自带一个开发用假供应商（`apps/api/dev/mock_provider.py`），
在本地起一个 OpenAI 兼容端点，让「工具调用 → 流式回答 → 表情包」整条链路闭环，**零成本**。

```bash
# 终端 1 —— 假供应商（127.0.0.1:8899）
cd apps/api && .venv/bin/python dev/mock_provider.py

# 终端 2 —— 后端（127.0.0.1:8000）
cd apps/api && .venv/bin/python -m uvicorn src.main:app --reload --port 8000

# 终端 3 —— 前端（localhost:3000）
cd apps/web && npm run dev
```

`.env` 里保留 `MOCK_API_KEY=dev` 即可。想用真模型时填 `DEEPSEEK_API_KEY`，
真 key 会**自动优先于 mock**（`providers.json` 里 mock 排在最后）。

### 验证

```bash
curl localhost:8000/health                            # 供应商与工具状态
cd apps/api && .venv/bin/python tests/test_smoke.py   # 21 项冒烟测试，不需要 key
```

`/health` 会区分 `ready` 与 `pending` —— 缺凭证的工具会明确列出来，排障不用猜。

## 二、环境变量

完整字段说明见 **[03-配置参考.md](03-配置参考.md)**。部署时最需要关心的只有几个：

| 变量 | 用在哪 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 后端 | 主供应商。**只在服务端，绝不下发浏览器** |
| `KIMI_API_KEY` | 后端 | 降级供应商，可选 |
| `DATA_HOME` | 后端 | **容器里设成 `/data` 并挂持久卷** |
| `API_ORIGIN` | 前端 | 后端根地址，供同源代理转发（默认 `http://localhost:8000`） |
| `APIFY_TOKEN` / `EBAY_API_KEY` | 后端 | 不配则对应工具显示 `pending`，**不会伪造数据** |

> ⚠️ **不要使用 `NEXT_PUBLIC_*` 前缀存放任何密钥。**
> 第一代把 `NEXT_PUBLIC_DEEPSEEK_API_KEY` 打包进了前端 bundle，
> 任何人打开 DevTools 就能拿走并盗刷。V2 已彻底移除这种用法。

## 三、前端 → Vercel

V2 是标准 Next.js 16 应用，Vercel 能自动识别，**不需要 `vercel.json`**。

1. Vercel → **New Project** → 导入 `Frank-789/VERTEX-PRO-V2`
2. **Root Directory 设为 `apps/web`** ← 关键，否则会去构建后端
3. 环境变量加 `API_ORIGIN` = 后端公网地址
4. Deploy

### 同源代理：为什么不需要配 CORS

`apps/web/next.config.ts` 把所有 `/api/v1/*` 转发到 `API_ORIGIN`：

```
浏览器 ──同源──▶ Vercel (Next.js) ──▶ 后端
                  /api/v1/*  →  ${API_ORIGIN}/api/v1/*
```

收益：

1. **消灭 CORS 那一整类故障** —— 后端不再需要维护 `ALLOWED_ORIGINS` 白名单
2. 后端地址不硬编码进客户端 bundle，换后端不用重新构建前端
3. 密钥全部留在服务端
4. 将来加鉴权，只需在 Next.js 中间件里拦一道

> 第一代的 CORS 是隐性炸弹：`ALLOWED_ORIGINS` 标了 `sync: false`，
> 线上值只存在于 Render 面板，仓库里看不见；配错则全站请求失败**且服务端无报错**。

## 四、后端 → Docker 常驻进程

### 为什么不能上 Serverless

| 智能体运行时的需求 | Vercel Serverless 的现实 |
|---|---|
| 常驻进程 | 无常驻进程 |
| 持久文件系统（`/data`） | 文件系统临时且只读 |
| 长时运行的定时调度（`issues/`） | 函数有时长上限 |
| 服务端持有密钥 | 每个请求都是公网入口 |

**这不是选择，是物理限制。** 所以后端要跑在 Docker / 任何常驻容器里。

### 用 docker compose 起（推荐）

```bash
cp .env.example .env      # 填上 DEEPSEEK_API_KEY
docker compose up -d
curl localhost:8000/health
```

### 或者只用 Dockerfile

**构建必须在仓库根目录执行** —— 镜像需要 `config/` 和 `prompts/`：

```bash
docker build -f apps/api/Dockerfile -t vertex-api .
docker run --rm -p 127.0.0.1:8000:8000 \
  -e DEEPSEEK_API_KEY=sk-xxx \
  -v vertex-data:/data \
  vertex-api
```

### 镜像契约

| 要点 | 为什么 |
|---|---|
| `tini` 作 PID 1 | 正确转发信号、回收僵尸进程。没有它 `docker stop` 会等到超时才杀掉 uvicorn |
| 非 root（UID 10001） | 最小权限 |
| `HEALTHCHECK` 打 `/health` | 编排器能判断存活，用 python 探活省掉装 curl |
| `/data` 持久卷 | 会话 / 事件 / 任务重启不丢 |
| `PYTHONDONTWRITEBYTECODE=1` | 配合只读的 `/app`，不产生 `.pyc` |
| `ALLOW_DEV_CORS=0` | 生产走同源代理，不需要 CORS |

端口默认只绑 **`127.0.0.1:8000`**。后端持有全部密钥且**目前没有鉴权**，
不要改成 `"8000:8000"` 裸挂公网 —— 要远程访问请走 HTTPS 反代或 SSH 隧道。

### ⚠️ 一个不能改的约束：目录层级

`core/paths.py` 用 `Path(__file__).resolve().parents[4]` 推算仓库根：

```
src/core/paths.py → src/core → src → api → apps → 仓库根
```

所以镜像里**必须保持** `apps/api/src/` 这个深度。打平成 `/app/src/` 会让
`parents[4]` 越界，**所有路径解析全错，而且是静默失败**。

同理，`docker-compose.yml` 里显式设了 `DATA_HOME` / `CONFIG_HOME` / `PROMPTS_HOME`，
不依赖这个推算。

> 📌 **验证状态**：路径解析逻辑已在模拟的容器目录结构下验证通过；
> 但**镜像本身尚未实际构建过**（开发机上没有 Docker）。
> 首次构建如遇问题，优先怀疑 `requirements.txt` 的版本兼容性。
